# circle.animaation.proto-1

Зацикленная 3D-анимация золотого логотипа (three.js + postprocessing).

## Запуск

    npm install
    npm run dev      # http://localhost:5173
    npm run build    # сборка в dist/

При первом открытии отображается тёмный экран подготовки сцены. Он исчезает **после первого WebGL-кадра и загрузки шрифтов**, не попадая в видеозапись. Если модули не загрузились или WebGL недоступен, вместо белой страницы появится сообщение об ошибке с кнопкой «Повторить загрузку». Ошибки сторонних скриптов, которые может добавлять прокси предпросмотра (например, Cloudflare Insights), не считаются ошибкой загрузки приложения. Проверка обоих случаев: `npm run verify:loader` (контрольный кадр: [`docs/loader-preview.jpg`](docs/loader-preview.jpg)).

## Интро — первый ролик программы

**№1 — открытие, не экран ожидания.** Откройте `?scene=intro` (старый `?scene=waiting` тоже работает). После короткой темноты из верхнего левого света приходит тонкая игла и ставит первую точку построительной окружности → её световой наконечник ведёт тонкую ленту с коротким сужающимся хвостом → передаёт движение контуру циркуля → при превращении чертежа в объёмное золото от знака расходится волна из мягких лучей и камера действительно наезжает на металл → проявление из тени → когда подпись закончена, короткий штрих запирает композицию → удержание с пульсацией и
плавным увеличением → последовательный уход даты, подзаголовка и названия → уход золота →
детали контура уходят, последняя дуга отматывается к первой точке → тёмная пауза → повтор.
Первый ролик длится **15,3 с** и при экспорте цепочки воспроизводится один раз; в предпросмотре он зациклен для проверки шва. Полностью собранная композиция остаётся читаемой около **5,1 с** до начала ухода. Три контрольных кадра: [холодный старт](docs/intro-overture.jpg), [световое раскрытие](docs/intro-impact.jpg), [финальный штрих](docs/intro-signature.jpg). Длительности фаз меняются в панели настроек. Буквы в каждой строке сначала по очереди гравируются тонким контуром, затем по очереди заполняются золотом; надписи слегка поднимаются на место. Крайние кольца медленно строятся дугами вместе с рисками, рядом на короткое время возникают солнечные блики и мягкое боке. Те же движения повторяются в браузерной записи. Время анимации не замедляется при падении частоты кадров.

## Настройки
⚙ в правом верхнем углу (или клавиша S). Пробел — пауза. Двойной клик по ползунку — сброс.
- **Экспорт JSON** — копировать/скачать текущие настройки.
- **Импорт** — вставить JSON и «Применить».
- **Сброс** — значения первой сцены из `src/scenes/waiting.js` (`WAITING_DEFAULTS`).

Чтобы присланный JSON стал значением по умолчанию, перенесите его в `WAITING_DEFAULTS` в `src/scenes/waiting.js` (`src/config.js` по-прежнему экспортирует совместимый `DEFAULTS`).
После обновления визуальных значений по умолчанию нажмите **Сброс** в панели: ранее сохранённые в браузере настройки продолжают действовать до сброса.

### Основные группы параметров
- `logo.depth`, `logo.bevel`, `logo.outlineWidthPx` — толщина логотипа, скос и контур (логотип растёт во время проявления).
- `lights.topGlow` — свечение над логотипом (центр кадра).
- `background.lowerShade` — затемнение нижнего левого угла; `background.godRays`, `background.brushed`, `background.fog` — лучи, диагональная текстура и туман.
- `timeline.ringsIntro` — длительность прорисовки крайних колец; `rings.speed` — скорость движения рисок; `rings.constructionOpacity` — пунктирная разметка «циркулем».
- `particles.rayLift` — подсветка пыли кольцами.
- `post.dofEnabled` — размытие (выключено, кадр чёткий); `post.chromaticAberration` — радиальная аберрация у краёв; `post.bloomIntensity` — блум.

Блики боке используют фрагмент [LYGIA `generative/random.glsl`](src/shaders/lygia-random.glsl); его [условия лицензии и уведомления](src/shaders/LYGIA-LICENSE.md) сохранены в репозитории. Применять этот код здесь разрешено с учётом подтверждённого некоммерческого статуса проекта; при изменении назначения нужно заново проверить лицензию.

## Основа для серии

Смена фреймворка не требуется: `src/runtime.js` отвечает за абсолютное время, паузу и точный `renderAt(t)` через интерфейс `update/render`, не импортируя Three.js. `src/scenes/catalog.js` задаёт единый формат **1920×1080 / 60 FPS** и план девяти видов. **Реализованы виды №1, 2, 8 и 9:** вступительное интро (`src/intro-scene.js`), фирменный фон (`src/brand-scene.js`), фотопауза (`src/photo-pause-scene.js`) и финал (`src/finale-scene.js`). Внутренний id `waiting` для №1 оставлен ради совместимости ссылок, JSON-настроек и старых экспортов. Виды №3–7 остаются планами, а не фиктивными роликами.

`npm run typecheck` постепенно проверяет типы движка и описаний сцен без перевода шейдеров на другой язык. `npm run verify:render`, `npm run verify:brand` и `SCENE=photo-pause npm run verify:priority` и `SCENE=finale npm run verify:priority` проверяют покадровый шов и наличие титра в экспортном canvas.

## Производительность без снижения качества

Профилирование покадрового рендера показало, что обновление сцены занимает около **2,4 мс**, а основное время уходит в GPU-постобработку. Раньше отдельный полноэкранный проход DOF исполнялся даже при `post.dofEnabled = false` и нулевой прозрачности: в software Chromium это добавляло примерно **3,9 с** к кадру. Теперь такой проход полностью пропускается, а при включении настройки возвращается без пересборки цепочки вывода. Остальные эффекты и параметры качества не изменились: **1920×1080 / 60 FPS**, 4× MSAA, SMAA Ultra, bloom, хроматическая аберрация, виньетка и ACES.

На контрольном кадре время снизилось с **8,5 с до 4,4 с** (ускорение **1,94×** в software Chromium; на целевом GPU абсолютные значения будут другими). Сравнение с эталонным нулевым DOF-проходом: не более **1/255** отличия на **132 из 2 073 600** пикселей, на кадре шва отличий нет.

Следующий профиль CPU показал, что основная нагрузка в `update()` приходилась на десятки одинаковых `style.setProperty` для титра и покадровые аллокации `THREE.Color`. Теперь узлы и последние значения CSS кэшируются, а цвета и служебные массивы переиспользуются. В отдельном A/B-прогоне 200 обновлений сцены заняли **73,7 мс → 38,8 мс** (**1,9×** быстрее), при этом GPU-время не изменилось, а кадры всех четырёх готовых видов на удержании и шве попиксельно идентичны. `npm run verify:performance` дополнительно проверяет кэш титра и стоимость `update()`. Пониженного пресета рендера нет.

## Настройки, шрифты и JSON

Кнопка ⚙ видна в правом верхнем углу **во всех четырёх сценах** и не гаснет при бездействии; панель открывается кликом или клавишей **S**. Вверху панели — вкладки `01 · Интро`, `02 · Фирменный фон`, `08 · Фотопауза`, `09 · Финал`: каждая сцена имеет полный собственный набор настроек, включая таймлайн, текст, шрифт, композицию, декор, свет и постобработку. Изменения сохраняются в `localStorage` и сразу перерисовывают кадр.

Шрифты: встроены `Cormorant Garamond`, `PT Serif`, `Playfair Display`, `Montserrat` (кириллица через `@fontsource`), плюс загрузка своего `.ttf/.woff2/.otf` через `FontFace`. В разделе «Текст и шрифт» настраиваются строки, начертание, число контурных линий, толщина обводки, задержка заливки и свет пера; DOM-титр и покадровый экспорт используют один и тот же конфиг.

Панель умеет **копировать/скачивать JSON всего проекта v2**, импортировать его, применять как defaults, сбрасывать одну сцену или все сцены, копировать ссылку `?config=…` и запускать рендер с текущими настройками. Присланный JSON можно вставить в панель или открыть как ссылку: настройки применяются без перезагрузки, после чего доступна покадровая запись WebM. Проверка: `npm run verify:config`.

## Интерфейс

Панели сделаны строже и минималистичнее, чтобы не перекрывать кадр. Нижний пульт — тонкая полупрозрачная полоса: он скрывается при бездействии, возвращается по движению мыши или наведению на нижнюю кромку, а запись одного цикла и всей цепочки убрана в меню `···`. Панель настроек стала компактным правым drawer с короткими вкладками `01/02/08/09`; второстепенные действия (экспорт видео, рендер, сбросы) тоже в меню `···`. Кнопка ⚙ остаётся видимой, но маленькой и ненавязчивой. Интерфейс никогда не попадает в покадровый WebM.

## Пульт показа и монтажная шкала

Курсор над заставкой больше не скрывается. Пульт внизу и кнопка ⚙ первой сцены появляются при движении мыши и уходят после 3,2 с бездействия; при работе с настройками или клавиатурной фокусировке не прячутся. **R** закрепляет/открепляет пульт.

- Кнопки **01 / 02 / 08 / 09** переключают готовые виды без перезагрузки страницы: стоп-кадр с титрами прежнего вида плавно растворяется в новом за 0,9 с.
- По умолчанию переход **ручной**. «Авто: вкл.» включает цепочку **01 → 02 → 08 → 09 → 01** после каждого цикла; для длительной речи оставьте авто выключенным. При записи переключение заблокировано.
- Ползунок прокручивает **текущий** цикл, рядом таймкод и шаг **−1 / +1 кадр** (стрелки клавиатуры). Перемотка ставит сцену на паузу. Поле «Цикл» изменяет длительность, корректируя фазу удержания, не качество рендера. Для финала минимум 16 с, для №2/8 — 11 с, чтобы фразы и обратный выход успели завершиться.
- Пульт не входит в кадр, не добавляет звук и не меняет формат видео. **«● Цикл»** покадрово кодирует один цикл текущего вида; **«● Вся цепочка»** кодирует одним WebM 01 → 02 → 08 → 09 с теми же плавными переходами. Оба режима выводят каждый кадр по абсолютному времени и записывают строго **1920×1080 / 60 FPS**, даже если рендер идёт медленнее реального времени. Под пультом показывается прогресс и кнопка «Отменить». Запись цепочки всегда начинается с 01, даже если сейчас открыт другой вид, и заканчивается на 09; повторяющееся автоматическое воспроизведение в файл не входит. На время записи переключение и перемотка блокируются. Пауза — кнопка ▶/Ⅱ или пробел; на первой сцене сохраняется полная панель настроек ⚙.

Проверка управления и переходов: `npm run verify:operator`; покадрового WebM (15 кадров ускоренного тестового сценария, проверка каждого закодированного кадра и отмены): `npm run verify:offline`. Прежний тест записи в реальном времени: `npm run verify:chain` (нужны запущенный сервер и Chromium).

## Фирменный фон

Откройте `?scene=brand` (например, `http://localhost:5173/?scene=brand`). Циркуль опущен ниже, но остаётся по центру **над** надписью «Янтарный циркуль»; даты нет. Положение задаётся в настройках сцены (`Композиция → Лого: Y`). На фоне — приглушённая вариация света первой заставки: постепенно строятся крайние золотые кольца, движутся пыль, туман и лучи, а циркуль проявляется из контура с небольшим количеством искр. Его настоящий SVG-силуэт расходится полупрозрачными затухающими волнами; металл слегка поворачивается в 3D, не переворачиваясь. Титр сначала гравируется по буквам, затем заполняется; на выходе заливка, контур, символ и кольца уходят в обратном порядке до тёмного бесшовного кадра. Фон подходит для речи, ужина и музыкальных сетов: середина **24-секундного** цикла постоянно живая, без отвлекающих крупных движений. В нижнем пульте есть пауза, запись одного цикла WebM и кнопки 01/02/08/09; в экспорт они не попадают. [Контрольный кадр](docs/brand-background.jpg) и [покадровый сценарий](docs/brand-animatic.md). `npm run verify:brand` проверяет фон, вертикальную композицию, текст в canvas и шов; `npm run verify:motion` сравнивает реальные пиксели фона на удержании и точность повторного кадра после перемотки во всех трёх видах.

## Фотопауза и финал

- `?scene=photo-pause` (№8): 24 с, **та же ось и масштаб циркуля, что у №2**, мягко появляющаяся рамка видоискателя и титр «Фотопауза» под ним. Фон чуть тише и симметричнее, но постоянно движется: кольца, пыль, лучи и затухающие контурные волны. Вход и обратный выход повторяют кинематографический ритм №1; первый и последний кадры совпадают. [Контрольный кадр](docs/photo-pause.jpg).
- `?scene=finale` (№9): 18 с; на том же живом золотом фоне сначала прорисовывается циркуль, затем **под ним** посимвольно контуры и заливки «Янтарный циркуль», затем «История продолжается». Волны за знаком уменьшены, чтобы не пересекать название. На выходе фраза, название, циркуль и кольца исчезают в обратном порядке; тёмный шов перед следующим циклом. [Контрольный кадр](docs/finale.jpg).

Без дополнительных надписей и звука. У каждого вида собственный таймлайн, но тот же экспортный canvas 1920×1080 и покадровая запись WebM через кнопку «● Цикл». При необходимости проверить оба вида: `SCENE=photo-pause npm run verify:priority` и `SCENE=finale npm run verify:priority` (сервер должен работать). Нажатие номера в панели переключает предпросмотр.

## Видео и проверка рендера
Первая заставка — логотип, «Янтарный циркуль», «Вечер ретроспектива», 20 ноября 2026 года.
Кадр всегда выводится в **1920×1080** с MSAA, SMAA и постобработкой; режим пониженного качества не предусмотрен.
Подпись и логотип рассчитываются по абсолютному времени кадра, а частицы создаются с фиксированным зерном случайности: перемотка и покадровый рендер воспроизводимы без «прогрева» анимации.

1. `npm ci` и `npm run dev` (оставить сервер запущенным).
2. Указать `CHROME=/путь/к/chrome` (Chromium/Chrome) или выполнить `scripts/setup-headless.sh` для портативного Chromium.
3. `npm test` — быстрые тесты таймлайна без браузера; `npm run verify:render` — проверка в браузере (ошибки, перемотка, шов и разрешение).
4. `FPS=60 OUT=out/frames npm run render:frames` — PNG-кадры одного цикла. Длительность и задержка считываются из текущих настроек браузера. Кадры нумеруются `f00000.png` и далее; последний кадр находится **перед** концом цикла.
5. `FPS=60 IN=out/frames OUT=out/logo-loop.mp4 npm run render:encode` — MP4 через установленный `ffmpeg`. Для монтажа без потерь используйте непосредственно PNG-последовательность.

Арт-дирекшен первой заставки, покадровый план и контрольные style frame: [`docs/animatic.md`](docs/animatic.md). Отбор GitHub-инструментов и эффектов с лицензиями и критериями внедрения: [`docs/github-motion-research.md`](docs/github-motion-research.md). Семь обзорных кадров можно переснять командой `OUT=docs/storyboard npm run render:storyboard` (они не заменяют финальный PNG-рендер).

`URL=http://localhost:5173/` можно переопределить для команд с браузером. Экспорт из панели настроек и пульта теперь использует WebCodecs VP9 и [Mediabunny](https://github.com/Vanilagy/mediabunny) (MPL-2.0) для WebM: **40 Мбит/с, фиксированные 60 FPS**, без звука и пониженного пресета. Нужен браузер с WebCodecs (например, актуальный Chrome/Edge и защищённый контекст HTTPS или localhost). Стандартная цепочка — 4878 кадров / 81,3 с видео; обработка может занять существенно больше времени и потребовать несколько сотен МБ свободной памяти для готового файла. Не закрывайте вкладку до завершения или отмены.
На шве есть короткий полностью тёмный участок: он скрывает непрерывное движение фонового шума и колец. `verify:render` сравнивает реальные пиксели первого и последнего кадра при 60 FPS; для стандартных настроек они совпадают. При изменении длительностей фаз проверьте шов заново.
