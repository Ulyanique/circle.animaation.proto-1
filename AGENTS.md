# Заметки для следующего агента

## Назначение

Это браузерный конструктор четырёх фирменных золотых заставок: 01 интро (`waiting`), 02 фон (`brand`), 08 фотопауза и 09 финал. Пользователь хочет гибкое редактирование с профессиональным UI в духе After Effects, но не буквальную копию и не потерю существующей композиции. Работайте постепенно, не выдавайте неподдерживаемые функции за готовые.

## Перед изменениями

- Прочитайте `README.md`, `docs/architecture.md`, `docs/constructor-plan.md` и относящиеся к задаче файлы. В дереве могут быть значительные незакоммиченные изменения пользователя и предыдущих агентов; не откатывайте их.
- Основная архитектура: Three.js сцены, DOM-титры, canvas-композитор и Vite. Настройки независимы для каждой сцены; совместимость старых JSON принципиальна.
- Пользователю важен покадровый экспорт одного цикла и цепочки 01→02→08→09 в 1920×1080/60 fps без пропущенных кадров и изменения длительности. Текущий путь: `src/offline-video.js`, Mediabunny/WebCodecs, `src/main.js`, `src/scene-transition.js`. В UI доступна отмена. Экспорт без звука.
- Настройки и рамки редактора не должны попадать в кадр или менять экспорт. Изменения DOM-титров проверяйте и в `src/caption-compositor.js`: предпросмотр и экспорт должны совпадать, включая шрифты, трекинг, прозрачность, автоподгонку и анимацию.

## Редактор и ограничения

- `src/editor.js`, `src/editor-layers.js`, `src/editor-history.js`, `src/editor-timeline.js`, `src/editor-workspace.js`, `src/editor-preview.js`, `src/styles.css` — список слоёв, инспектор, история, таймлайн, панели и масштаб просмотра. Проверьте desktop, узкий экран, клавиатуру, блокировки и undo/redo.
- Таймлайн показывает штатные элементы, но строки «Сценарий» не означают редактируемые или известные точные интервалы. Своё время есть только у поддерживаемых дополнительных элементов и чертёжных линий; ключевых кадров и свободного порядка всех объектов пока нет.
- Порядок добавленных эффектов (`src/effect-order.js`) выключен по умолчанию; он задаёт `renderOrder` рисуемым объектам, сохраняет depth-test и оставляет чёрную шторку выше. Смешивание со штатными прозрачными объектами может меняться. Не использовать `Group.renderOrder` как универсальное решение.
- Предпросмотр имеет масштаб, панорамирование и CSS-обрезку; при закрытии редактора сбрасывается. Учитывайте это при расчёте рамок, безопасных полей и сравнении DOM/canvas. Экспорт запускается после закрытия редактора.
- Слои имеют лимиты, имена и блокировку геометрии; изменения должны корректно работать с историей, копированием и сохранением. Блокировка геометрии не является общей блокировкой всех параметров.

## Проверка

- `npm test`, `npm run typecheck`, `npm run build`, `git diff --check`.
- Запустите Vite: `npm run dev -- --port 5175`. Для браузерных тестов удобно явно задать `URL=http://localhost:5175`, например `URL=http://localhost:5175 npm run verify:editor:lite`. Используйте свежий dev-server: при накопленных HMR-версиях одного модуля проверки контуров шрифтов могут работать с разными экземплярами.
- `verify:frame-determinism` сравнивает реальные композитные кадры всех четырёх сцен при разных порядках перемотки (по умолчанию уменьшенный WebGL). `SCENES=waiting RENDER_WIDTH=1920` запускает полное разрешение для одной сцены. Не вносите изменения в файлы, пока идёт такой прогон Vite: HMR перезагрузит страницу.
- Выбирайте проверки по изменению: `verify:effect-order`, `verify:custom-fonts`, `verify:custom-opacity`, `verify:custom-reveal`, `verify:caption:fit`, `verify:transitions`, `verify:offline-video`. Часть тестов требует браузера/WebGL и работает медленно; проверка реального полного MP4 ещё дороже.
- Отличайте юнит-тест, покадровый технический smoke-test, просмотр отдельных кадров и просмотр полного готового видео. Не заявляйте визуальную или экспортную проверку, если она не выполнена. Синтетический рендер и скриншот — не гарантия качества на реальном экране.
- `ffmpeg`/`ffprobe` могут отсутствовать; не заменяйте ими браузерный экспорт без отдельного решения. `scripts/verify-offline-video.cjs` использует имеющийся путь проверки; уточняйте окружение перед установкой инструментов.

## Внешние проекты

См. `docs/external-tools-audit.md`: оценены все десять проектов пользователя, указаны ревизии, ограничения и лицензии. Самые полезные направления — дисциплина оценки реального рендера из motion-video-kit/motionmaxxing, изолированное изучение детерминированной модели OpenFilm и опциональная диагностика ffmpeg-skill при наличии FFmpeg. Пользователь уточнил: продукт предназначен для одного человека и локальных экспериментов, распространение не предусмотрено. Не делать лицензии главной темой и не тормозить исследование ими; в первую очередь оценивать практическую пользу, совместимость и возможность локального запуска. Не заменяйте существующий стек без согласования и не заявляйте, что внешние инструменты проверены запуском, если они не запускались.
