# Архитектура заставок — инкрементальный этап

Сохраняем Three.js/WebGL + Vite и два реализованных вида. Переход на новый рендерер или React не нужен для покадрового видео: важнее неизменные кадры, последовательность и возможность вернуться к любому `t` без прогрева.

- `src/scenes/catalog.js` — один формат 1920×1080, 60 FPS и **план** девяти видов. `waiting` и `brand` имеют статус `ready`; остальные не выданы за работающие сцены.
- `src/scenes/waiting.js` — параметры первой заставки, извлечённые из `src/config.js` без изменения значений. `config.js` остаётся совместимым с UI, JSON и прежними сохранёнными настройками браузера.
- `src/runtime.js` — без DOM и WebGL: длительность цикла, `advance(elapsed)` с учётом паузы и скорости, независимый `renderAt(t)` через `update(t,dt)/render(dt)` адаптера.
- `src/scene.js` — адаптер Three.js первой заставки; `src/brand-scene.js` переиспользует его высококачественный рендерер, но задаёт своё статичное фирменное поле и независимый таймлайн 24 с. `src/main.js` выбирает готовую сцену по `?scene=brand` (или `waiting` по умолчанию), подключает движок и запись.
- Единый `drawCompositeFrame` в `main.js` используется и браузерной записью WebM, и проверкой `compositeFrameAt(t)`. Последняя возвращает canvas реального размера, чтобы проверить наличие титра в экспорте.

**Инварианты:** 1920×1080 без второго пресета; абсолютное время, детерминированный seek и пиксельный шов; неизменные художественные настройки первой заставки 15,3 с и самостоятельный спокойный цикл фирменного поля 24 с. Загрузчик/панели — только интерфейс просмотра, не часть экспортируемого кадра. LYGIA остаётся в проекте с сохранённой лицензией при подтверждённом некоммерческом использовании.

## При добавлении третьей сцены

1. Согласовать содержание и тайминг; запись `planned` в каталоге сама по себе не создаёт ролик.
2. Добавить описание параметров и отдельный адаптер с `update(t,dt)`/`render(dt)` либо повторно использовать существующий, не меняя поведение двух готовых видов.
3. Включить вид в каталог как `ready` только с работающим адаптером и отдельным хранением настроек, если для него появится собственная панель.
4. Записать референсные кадры и пройти `npm test`, `npm run typecheck`, `npm run build`, `npm run verify:loader`, `npm run verify:render`, `npm run verify:brand`; проверить экспорт в браузере на целевом экране.

Типизация сейчас намеренно охватывает только чистый runtime и описание сцен (`tsconfig.json`). Перевод шейдеров/рендерера на TypeScript — отдельное решение после двух-трёх реальных заставок, если появится измеримая проблема сопровождения.
