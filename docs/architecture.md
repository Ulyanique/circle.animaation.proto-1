# Архитектура заставок — инкрементальный этап

Сохраняем Three.js/WebGL + Vite и четыре реализованных вида (№1, 2, 8, 9). Переход на новый рендерер или React не нужен для покадрового видео: важнее неизменные кадры, последовательность и возможность вернуться к любому `t` без прогрева.

- `src/scenes/catalog.js` — один формат 1920×1080, 60 FPS и **план** девяти видов. `waiting`, `brand`, `photo-pause` и `finale` имеют статус `ready`; виды №3–7 не выданы за работающие сцены.
- `src/scenes/waiting.js` — параметры первой заставки, извлечённые из `src/config.js` без изменения значений. `config.js` остаётся совместимым с UI, JSON и прежними сохранёнными настройками браузера.
- `src/runtime.js` — без DOM и WebGL: длительность цикла, `advance(elapsed)` с учётом паузы и скорости, независимый `renderAt(t)` через `update(t,dt)/render(dt)` адаптера.
- `src/scene.js` — адаптер Three.js первой заставки; `src/brand-scene.js` переиспользует его высококачественный рендерер, но задаёт своё статичное фирменное поле и независимый таймлайн 24 с. `src/photo-pause-scene.js` добавляет рамку видоискателя, `src/finale-scene.js` последовательно открывает символ, название и фразу; чистые такты и защита шва находятся в `src/scenes/cues.js`. `src/main.js` выбирает адаптер по `?scene=waiting|brand|photo-pause|finale`, подключает движок и запись.
- Единый `drawCompositeFrame` в `main.js` используется и браузерной записью WebM, и проверкой `compositeFrameAt(t)`. Последняя возвращает canvas реального размера, чтобы проверить наличие титра в экспорте.

**Инварианты:** 1920×1080 без второго пресета; абсолютное время, детерминированный seek и пиксельный шов; неизменные художественные настройки первой заставки 15,3 с и самостоятельные циклы фирменного поля/фотопаузы по 24 с, финала 18 с. Загрузчик/панели — только интерфейс просмотра, не часть экспортируемого кадра. LYGIA остаётся в проекте с сохранённой лицензией при подтверждённом некоммерческом использовании.

## При добавлении следующего вида (№3–7)

1. Согласовать содержание и тайминг; запись `planned` в каталоге сама по себе не создаёт ролик.
2. Добавить описание параметров и отдельный адаптер с `update(t,dt)`/`render(dt)` либо повторно использовать существующий, не меняя поведение четырёх готовых видов.
3. Включить вид в каталог как `ready` только с работающим адаптером и отдельным хранением настроек, если для него появится собственная панель.
4. Записать референсные кадры и пройти `npm test`, `npm run typecheck`, `npm run build`, `npm run verify:loader`, `npm run verify:render`, `npm run verify:brand`, `SCENE=photo-pause npm run verify:priority`, `SCENE=finale npm run verify:priority`; проверить экспорт в браузере на целевом экране.

Типизация сейчас намеренно охватывает только чистый runtime и описание сцен (`tsconfig.json`). Перевод шейдеров/рендерера на TypeScript — отдельное решение после двух-трёх реальных заставок, если появится измеримая проблема сопровождения.
