# Архитектура заставок — инкрементальный этап

Сохраняем Three.js/WebGL + Vite и четыре реализованных вида (№1, 2, 8, 9). Переход на новый рендерер или React не нужен для покадрового видео: важнее неизменные кадры, последовательность и возможность вернуться к любому `t` без прогрева.

- `src/scenes/catalog.js` — один формат 1920×1080, 60 FPS и **план** девяти видов. `waiting`, `brand`, `photo-pause` и `finale` имеют статус `ready`; виды №3–7 не выданы за работающие сцены.
- `src/scenes/waiting.js` — параметры стартового интро; историческое имя сохранено для совместимости. `src/scenes/brand.js`, `photo-pause.js` и `finale.js` получают полный конфиг через `createSharedSceneConfig` (`src/scenes/shared-visuals.js`), поэтому у каждой сцены свой независимый набор значений, а не общая копия интро.
- `src/config.js` — схема полей, `SCHEMA`, загрузка и сохранение настроек **отдельно для каждой сцены** (`circle-anim-settings-v2:<сцена>`), частичный импорт через `mergeConfig`, экспорт одной сцены (`configToJSON`) и всего проекта (`projectToJSON` / `parseProjectJSON`). Старый общий ключ `circle-anim-settings-v1` читается один раз как настройки интро.
- `src/ui.js` — панель ⚙ с вкладками 01/02/08/09: вкладка переключает сцену и её набор параметров, правки сразу применяются к живому рендеру и сохраняются под ключом этой сцены. Экспорт сцены, экспорт проекта, импорт JSON сцены или файла `scenes`, сброс только текущей сцены.
- `src/runtime.js` — без DOM и WebGL: длительность цикла, `advance(elapsed)` с учётом паузы и скорости, независимый `renderAt(t)` через `update(t,dt)/render(dt)` адаптера.
- `src/scene.js` — адаптер Three.js стартового интро с собственным световым раскрытием и движением камеры. `src/brand-scene.js` переиспользует рендерер для живого фирменного поля с контурными волнами и независимым таймлайном 24 с; в интро фоновых контуров нет. `src/photo-pause-scene.js` добавляет рамку видоискателя, `src/finale-scene.js` последовательно открывает символ, название и фразу; чистые такты и защита шва находятся в `src/scenes/cues.js` и `src/timeline.js`. `src/main.js` выбирает адаптер по `?scene=intro|brand|photo-pause|finale`; старый адрес `?scene=waiting` остаётся совместимым.
- `src/operator.js` — единый пульт, шкала точного seek, изменение длительности через holdDuration и явный переключатель ручного/автоматического режима. `main.js` снимает 1920×1080 композит уходящей сцены и растворяет его поверх нового WebGL-кадра за 0,9 с без перезагрузки и потери текста. Во время записи одного цикла ручной переход блокируется. `RECORDING_CHAIN` задаёт порядок однократной записи 01 → 02 → 08 → 09: одна MediaRecorder-сессия держит canvas 1920×1080 открытым через все сцены; на каждом переходе тот же снимок уходящего композита смешивается с новым кадром за 0,9 с прямо в экспортном canvas. Конструкторы WebGL могут задержать кадр на слабом устройстве, поэтому запись остаётся реального времени, а не офлайн-кодированием 60 FPS. Панели и переходный DOM-оверлей не попадают в файл.
- Единый `drawCompositeFrame` в `main.js` используется и браузерной записью WebM, и проверкой `compositeFrameAt(t)`. Последняя возвращает canvas реального размера, чтобы проверить наличие титра в экспорте.

**Инварианты:** 1920×1080 без второго пресета; абсолютное время, детерминированный seek и пиксельный шов; цикл интро по умолчанию 18,6 с и самостоятельные циклы фирменного поля/фотопаузы по 24 с, финала 18 с. Загрузчик/панели — только интерфейс просмотра, не часть экспортируемого кадра. LYGIA остаётся в проекте с сохранённой лицензией при подтверждённом некоммерческом использовании.

## При добавлении следующего вида (№3–7)

1. Согласовать содержание и тайминг; запись `planned` в каталоге сама по себе не создаёт ролик.
2. Добавить описание параметров и отдельный адаптер с `update(t,dt)`/`render(dt)` либо повторно использовать существующий, не меняя поведение четырёх готовых видов.
3. Включить вид в каталог как `ready` только с работающим адаптером; полный конфиг из `createSharedSceneConfig` даёт ему отдельное хранение настроек и вкладку в панели автоматически.
4. Записать референсные кадры и пройти `npm test`, `npm run typecheck`, `npm run build`, `npm run verify:loader`, `npm run verify:render`, `npm run verify:brand`, `SCENE=photo-pause npm run verify:priority`, `SCENE=finale npm run verify:priority`, `npm run verify:operator`; проверить экспорт в браузере на целевом экране.

Типизация сейчас намеренно охватывает только чистый runtime и описание сцен (`tsconfig.json`). Перевод шейдеров/рендерера на TypeScript — отдельное решение после двух-трёх реальных заставок, если появится измеримая проблема сопровождения.
