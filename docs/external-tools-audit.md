# Внешние инструменты для моушн-дизайна: оценка применимости

Проверены README и метаданные репозиториев по указанным ревизиям. Пользователь уточнил, что продукт предназначен для одного человека и локальных экспериментов; распространение не предусмотрено. Поэтому основной критерий — техническая польза и совместимость. Инструменты не устанавливались и не запускались; заявленные скорость и качество самостоятельно не проверены. Указанные лицензии — справочная информация, а не основание отказываться от локального исследования.

## Что делать дальше

1. **Сейчас:** применять собственный чек-лист проверки композиции, движения и переходов на фактическом экспортированном видео. Разделять автоматические метрики и художественную оценку; проверка отдельных кадров не равна просмотру ролика.
2. **Небольшой изолированный эксперимент:** изучить OpenFilm `frame(t)` и его проверку повторного рендера в разном порядке. Сравнивать с нашим детерминированным `runtime.renderAt`, не подключая пакеты к основному приложению и не объявляя совместимость без теста.
3. **При наличии системных FFmpeg/ffprobe:** опробовать ffmpeg-skill отдельно на копии экспортного файла для диагностики метаданных и проверки результата. Не заменять наш Mediabunny/WebCodecs экспорт только ради монтажа.
4. Motion-video-kit и motionmaxxing использовать как ориентиры для методики review, а не как гарант качества. Звук и озвучку не добавлять без отдельного решения пользователя: текущий экспорт без звука.

Скриншот на первой карточке показывает интерфейс Puck, а не подтверждённый интерфейс motionmaxxing; оценка выше основана на репозитории, а не на этой иллюстрации. Число звёзд и рекламные формулировки на карточках не подтверждают применимость или качество.
