# План: из четырёх роликов — кастомизированный конструктор

Документ фиксирует, что именно просил заказчик, что уже есть в коде, и в каком
порядке мы это делаем. Каждый этап заканчивается проверкой в `scripts/` и
обновлением `README.md`, чтобы «сделано» подтверждалось кадрами, а не словами.

## 3. Целевая архитектура

### 3.1. Конфиг v2 — один объект на весь проект

```json
{
  "version": 2,
  "output": { "width": 1920, "height": 1080, "fps": 60 },
  "scenes": {
    "intro": {
      "timeline": { "startDelay": 0.15, "speed": 1, "loop": true },
      "beats": [
        { "at": 0.00, "target": "centerRing", "anim": "draw",    "duration": 1.1 },
        { "at": 0.90, "target": "logo",       "anim": "emerge",  "duration": 1.6 },
        { "at": 2.40, "target": "cornerRings","anim": "draw",    "duration": 1.6 },
        { "at": 3.90, "target": "logo",       "to": { "y": 0.10 }, "duration": 1.2 },
        { "at": 4.30, "target": "title",      "anim": "trace",   "duration": 1.8 },
        { "at": 5.00, "target": "subtitle",   "anim": "trace",   "duration": 1.3 },
        { "at": 5.40, "target": "date",       "anim": "trace",   "duration": 1.0 }
      ],
      "elements": {
        "logo": {
          "type": "logo3d", "x": 0, "y": 0.10, "scale": 0.47, "rotation": 0,
          "material": { "gold": "#c8962e", "metalness": 1, "roughness": 0.34 },
          "in":  "emerge-from-shadow",
          "out": "into-shadow"
        },
        "title": {
          "type": "text", "text": "Янтарный циркуль",
          "x": 0, "y": -0.62, "size": 7.2, "tracking": 0.08,
          "font": "cormorant-garamond", "case": "none", "weight": 600,
          "in": "trace-contour", "out": "erase-contour",
          "trace": { "passes": 3, "stagger": 0.05, "jitter": 0.3, "glow": 0.4 }
        },
        "subtitle": { "type": "text", "text": "Вечер ретроспектива", "…": "…" },
        "date":     { "type": "text", "text": "20 ноября 2026 года", "…": "…" },
        "cornerRings": { "type": "fx", "sides": ["left", "right"], "…": "…" },
        "brackets":   { "type": "decor", "style": "corners", "…": "…" },
        "ringText":   { "type": "text-on-circle", "text": "фотопауза", "repeat": 6, "…": "…" }
      },
      "post": { "bloomIntensity": 0.6, "dofEnabled": true, "…": "…" }
    },
    "brand": { "…": "…" }, "photo-pause": { "…": "…" }, "finale": { "…": "…" }
  }
}
```

Правила:

* `x` / `y` — доли кадра от центра (−0.5…0.5 по X, −0.5…0.5 по Y), а не мировые
  единицы; так настройки читаются одинаково на любом разрешении.
* `beats` — единственное место, где описана хореография. Сцена больше не
  «зашивает» последовательность в `if (ph.local > …)`, а проигрывает дорожки.
* `elements` — то, что видит редактор и обводит рамкой выделения.
* Пресеты (`in` / `out`) — ссылки на реализацию в `src/presets.js`, поэтому
  редактору не нужно знать физику каждого эффекта.

Отдельные `*_DEFAULTS` из `src/scenes/*.js` становятся JSON-файлами
`src/presets/{intro,brand,photo-pause,finale}.json` — тогда «присланный JSON как
умолчание» это буквально замена файла, без правки кода.

### 3.2. Слои рендера

```
#stage     WebGL (лого, кольца, боке, декор)   — three.js
#overlay   Canvas2D (титр, текст по кругу)     — один источник правды
#boot      экран загрузки
```

Титр переезжает из DOM в canvas-слой. Причина: сейчас одна и та же анимация
живёт дважды — CSS в предпросмотре и `caption-compositor.js` при записи.
Обрисовка букв «несколькими линиями» и выбор шрифта требуют извлечения контуров
глифов, а это делается только на canvas. Превью и видео станут идентичными по
построению. DOM-текст остаётся скрытым для доступности и для проверок.

### 3.3. Шрифты

`src/fonts.js` — реестр из 6 шрифтов с кириллицей (пакеты `@fontsource/*`):

| id | шрифт | характер |
|----|-------|----------|
| `cormorant-garamond` | Cormorant Garamond | текущий, антиква с высоким контрастом |
| `playfair-display` | Playfair Display | плотная антиква, крупные заголовки |
| `prata` | Prata | тонкая контрастная антиква |
| `pt-serif` | PT Serif | нейтральная читаемая антиква |
| `manrope` | Manrope | геометрический гротеск |
| `unbounded` | Unbounded | широкий акцидентный гротеск |

Шрифт грузится лениво (`document.fonts.load`) при выборе, контуры для обрисовки
берутся через `opentype.js` из того же `.woff2`; если контуры получить не
удалось — резервный путь: растеризация глифа + marching squares. В JSON
попадает только `id`, а не путь к файлу.

## 4. Этапы

### Этап 0. Кнопка настроек всегда на виду — **сделано**

- Снять `body:not(.scene-waiting)`-скрытие ⚙ и панели.
- Показывать ⚙ во всех четырёх сценах; в режиме простоя (`operator-idle`)
  оставлять полупрозрачной, но кликабельной.
- Панель не должна попадать в запись и в `OUT`-кадры (как сейчас с пультом).
- Проверка: `npm run verify:operator` расширяется — ⚙ существует,
  `display != none`, панель открывается в каждой сцене.

### Этап 1. Конфиг v2 и панель для каждой сцены — **частично сделано**

- `src/config-v2.js`: схема, миграция v1 → v2, `mergeDefaults`, валидация,
  нормализация координат.
- `configs` — `Map` по `sceneId`, `localStorage` ключ на сцену; переключение
  сцены сохраняет и подхватывает её набор.
- `src/ui.js`: вкладки сцен 01 / 02 / 08 / 09, дерево элементов, группы
  «Композиция», «Анимация», «Типографика», «Цвета», «Эффекты», «Постобработка».
- Кнопки: «Копировать JSON», «Скачать .json», «Применить», «Сброс к
  умолчанию», «Сделать текущим умолчанием» (пишет `localStorage`-пресет).
- `?scene=brand&cfg=<base64>` и `#cfg=` — ссылка, которая открывает сцену с
  чужими настройками; удобно для «посмотри, как я настроил».
- Проверки: `npm run verify:settings` — вкладки четырёх сцен, изоляция значений,
  живое применение правки, сохранение под ключом сцены, экспорт сцены и проекта,
  импорт сцены и проекта, сброс только текущей сцены, видимость ⚙ в простое.
  Пока реализованы отдельные настройки, вкладки и импорт/экспорт JSON. Ссылка,
  полная валидация, дерево элементов и дополнительные группы остаются в плане.
  Кадр панели: [settings-panel.jpg](settings-panel.jpg).

### Этап 2. Типографика и обрисовка букв — частично сделано

Реализован выбор шрифта из шести в каждой сцене, сохранение в JSON и применение
в композите записи. Кадр: [font-settings.jpg](font-settings.jpg); проверка
`npm run verify:fonts`. Добавлена экспериментальная обрисовка вдоль контуров глифов тремя линиями
в просмотре и кадре записи; визуальная проверка отложена для обратной связи пользователя.

- `src/fonts.js` + реестр шрифтов (см. 3.3), селектор в панели.
- `src/text-layer.js`: canvas-слой, контуры глифов (`opentype.js`), раскладка
  с трекингом, регистром и межстрочным расстоянием.
- `src/trace.js`: обрисовка буквы «несколькими линиями» — N проходов по
  контуру со сдвигом фазы и лёгким дрожанием, затем заливка; на выходе —
  обратная обрисовка (стирание).
- Удаление дублирующей CSS-анимации букв; `caption-compositor.js` вызывает тот
  же код, что и превью (файл сокращается, а не растёт).
- Настройки: шрифт, размер, трекинг, регистр, число проходов, скорость,
  пауза между буквами, дрожание, свечение, порядок (слева направо / по кругу).
- Проверки: `verify:caption` и `verify:caption:export` переписываются на новый
  слой; добавляется тест «контуры букв получены для всех 6 шрифтов».

### Этап 3. Хореография сцен через beats (3–4 дня)

- `src/beats.js`: дорожки (позиция, масштаб, прозрачность, прогресс обводки,
  z-уход) и проигрыватель; сцены читают `beats`, а не собственные условия.
- **01 интро** — ровно как просил заказчик: круг в центре → лого в центре →
  круги по углам → лого поднимается → надписи внизу.
- **02 фон** — лого ниже (уже 0,58 / y +0,86), плюс декоративный элемент:
  тонкая построительная окружность с медленно вращающимися засечками и
  «пылью» по орбите; настраивается отдельным блоком `decor`.
- **08 фотопауза** — первый вариант реализован; нужна визуальная оценка. Уголки-кронштейны по краям кадра, лого в центре, вокруг
  него по кругу повторяющийся текст `фотопауза •` (`text-on-circle`:
  радиус, скорость вращения, количество повторов, прозрачность).
- **09 финал** — первый вариант реализован; требуется визуальная оценка. Титр стирается обрисовкой → лого переезжает в центр →
  уходит в глубину и стирается контуром → замыкающий круг, как в конце интро.
- Проверки: `verify:intro` (порядок фаз по кадрам), `verify:priority`
  (08 и 09), `verify:motion` — плюс новые пиксельные проверки «уголки есть»,
  «текст по кругу есть», «в конце финала круг».

### Этап 4. Редактор: выделение, мышь, контекстное меню (5–7 дней)

- `src/editor/overlay.js`: рамки выделения над сценой, хит-тест по проектным
  bounding box, перетаскивание (пишет `x` / `y`), масштаб за уголок,
  поворот с Shift, привязка к центру и третям кадра.
- `src/editor/context-menu.js`: правый клик по элементу → «Положение»,
  «Пресет появления», «Пресет исчезновения», «Цвет», «Дублировать»,
  «Скрыть», «Сбросить элемент», «Скопировать элемент в JSON».
- `src/presets.js`: `emerge-from-shadow`, `trace-contour`, `spark-assembly`,
  `fade-in`, `into-shadow`, `erase-contour`, `fly-into-depth`, `dissolve`.
  У каждого — иконка, описание и параметры, которые панель показывает сама.
- Undo/redo (стек мутаций конфига), режим редактора по `E`, сохранение в
  `localStorage`, экспорт всего проекта одним JSON.
- В записи и в `npm run render` слой редактора полностью отключён.
- Проверки: `verify:editor` — перетаскивание меняет координаты в конфиге,
  меню открывается на всех типах элементов, после записи рамок в кадре нет.

### Этап 5. Рендер видео с любым конфигом (1–2 дня)

- `npm run render -- --config=settings.json --scene=intro|all --out=video/`.
- `scripts/render-config.cjs`: читает JSON, подставляет в сцену, пишет WebM
  (при наличии ffmpeg — mp4), детерминированно повторяет кадры.
- Прогон «все сцены по цепочке» с одним файлом настроек.
- Проверка: `verify:render-config` — рендер 3 секунд с изменённым JSON даёт
  другие пиксели, чем дефолт, и совпадает с превью.

## 5. Порядок и зависимости

```
Этап 0 (кнопка)  ──► Этап 1 (конфиг v2 + панель) ──► Этап 2 (шрифты, обрисовка)
                                   │                          │
                                   ▼                          ▼
                          Этап 3 (beats, сцены)  ──► Этап 4 (редактор) ──► Этап 5 (рендер)
```

Оценка: 0,5 + 2,5 + 3,5 + 3,5 + 6 + 1,5 ≈ **17–18 рабочих дней** при
сохранении текущих проверок на каждом шаге.

## 6. Решения по умолчанию (можно поменять одной строкой)

1. Титр рисуется в canvas-слое, DOM остаётся только для доступности.
2. Координаты в JSON — доли кадра, а не мировые единицы three.js.
3. Умолчания сцен живут в `src/presets/*.json` — присланный файл заменяет
   умолчание без правки кода.
4. Пресеты анимации — именованные функции, а не произвольные кривые в JSON.
5. Шесть шрифтов на старте; добавить седьмой — одна запись в реестре.
6. Редактор — только в предпросмотре; в экспорт не попадает никогда.

## 7. Что проверяется после каждого этапа

`npm test`, `npm run typecheck`, `npm run build`, профильные `verify:*`,
`npm run render:storyboard` и обновлённые контрольные кадры в `docs/`.
Ни один этап не считается готовым, пока кадр в `docs/` не показывает
изменение.
