# Дорожная карта: кастомизируемый конструктор заставок

**Статус:** план, реализация ещё не начата. Работа остаётся в ветке `arena/f07b9df3-circle-animaation-proto-1` и в уже открытом PR #2; без отдельной команды PR не сливаем и новые ветки не создаём.

Опорный кадр пользователя: [`intro-impact.jpg`](intro-impact.jpg) / присланный `image-5.png`. Текущие художественные настройки считаем «пресетом по умолчанию»: всё новое должно либо воспроизводить их пиксельно, либо быть отдельным выбираемым пресетом.

## Цели пользователя (что должно получиться)

1. **№1/intrо:** новая последовательность — сначала окружность в центре, затем лого в центре, затем прорисовываются круги по углам, затем лого чуть поднимается, и только после этого внизу прописываются надписи там, где они сейчас.
2. **№2/brand:** лого ниже, плюс отдельный декоративный фоновый элемент.
3. **Шрифты:** выбирать другие шрифты.
4. **Настройки:** в каждой сцене настраивается всё, включая постобработку; кнопка настроек видна всегда; JSON всех сцен копируется/скачивается/импортируется; присланный JSON можно сделать настройками по умолчанию и отрендерить видео с любыми настройками.
5. **Текст:** постепенная отрисовка, как у лого: каждая буква обрисовывается по контуру несколькими линиями, затем получает заливку.
6. **№8/photo-pause:** уголки по краям экрана, лого в центре, вокруг лого повторяющаяся по кругу надпись `фотопауза • фотопауза • фотопауза …`.
7. **№9/finale:** надписи стираются, лого перемещается в центр, затем удаляется от зрителя и стирается контуром; в конце — круг, которым сейчас завершается первый ролик.
8. **Конструктор:** каждый элемент перемещается мышью и управляется через контекстное меню: позиция, пресет анимации, появление/исчезновение, цвета, масштаб, порядок, тайминги; всё сохраняется в JSON.

## Неизменные инварианты

- Один экран **1920×1080 / 60 FPS**; профили других разрешений не нужны.
- Максимальное качество рендера по умолчанию; **никакого пониженного пресета**.
- `renderAt(t)` и покадровый экспорт остаются детерминированными; шов цикла и цепочки — пиксельно бесшовный.
- Ручные переходы по умолчанию, опциональная цепочка №1→№2→№8→№9→№1.
- Публичный `?scene=intro`, совместимый `?scene=waiting`; внутренний id `waiting` сохраняется.
- Акценты `IntroScene` не протекают в №2/8/9.
- Курсор над заставкой всегда виден; кнопка настроек **должна быть видна**, а не исчезать при бездействии.
- LYGIA и атрибуция сохраняются; некоммерческое использование подтверждено.
- Сцены №3–7 не реализуем до отдельного решения.
- PR #2 не сливать без отдельной команды.

## Целевая архитектура

### 1. `config/v2` как единственный источник правды

Новый формат вместо «одного `DEFAULTS`»:

```json
{
  "version": 2,
  "activeScene": "waiting",
  "scenes": {
    "waiting": { "...": "полный набор секций" },
    "brand": { "...": "полный набор секций" },
    "photo-pause": { "...": "полный набор секций" },
    "finale": { "...": "полный набор секций" }
  },
  "editor": { "enabled": false, "snap": 0.01, "grid": false, "selection": null }
}
```

Секции каждой сцены: `timeline`, `logo` (в т.ч. `x`, `y`, `scale`, `rotation`, `z`, `inPreset`, `outPreset`), `caption` (строки, шрифт, размер, интервалы, цвета, число контурных линий, задержки), `rings`, `background`, `decor`, `particles`, `sparks`, `lights`, `post`, `animation`, `elements` (трансформы и z-order для конструктора), `export`.

- Схема UI перестаёт быть захардкоженным `SCHEMA`: добавляется `config-schema.js` с метаданными полей (`range`, `color`, `bool`, `select`, `text`, `font`, `vec2`, `preset`, `keyframes`) и генерацией панели.
- `loadConfig`/`saveConfig`/`parseConfigJSON`/`configToJSON` работают со всеми сценами; старый `circle-anim-settings-v1` читается как `scenes.waiting` (миграция без потери).
- `configFor(id)` возвращает полный конфиг сцены; `BrandScene.renderConfig()` и жёсткие `update()`-перезаписи заменяются чтением `cfg`.
- Настройки панели привязываются к активной сцене: `settings.bindConfig(cfg)` при `switchScene`; `isActive()` всегда `true`.
- Кнопка ⚙ видна во всех сценах и не гасится `operator-idle`; панель остаётся скрытой до клика/клавиши **S**.
- В панели: вкладки «Интро / №2 / №8 / №9», «Скопировать JSON», «Скачать .json», «Вставить JSON», «Применить как defaults», «Сброс сцены», «Сброс всех», «Рендер с этими настройками». Импорт проверяется схемой, неизвестные ключи игнорируются, отсутствующие берутся из defaults.
- Для отправки ассистенту или рендера «с любыми настройками» добавляется `?config=` (строка/ссылка на JSON) и/или drag-and-drop `.json`; после импорта вызывается `runtime.renderAt(...)` и покадровый экспорт без перезагрузки страницы.

### 2. `CaptionRenderer` — общий рендер титра для экрана и WebM

- Уходим от дублирования «DOM + `drawCaption()`» к одному детерминированному canvas-рендереру, который по `t` и `cfg.caption` рисует кадр 1920×1080; live-превью показывает тот же canvas, экспорт берёт его без пересчёта макета.
- Каждая графема получает `outline` и `fill` прогрессы из существующего `glyphReveal()`; контур рисуется **несколькими линиями** (настраиваемое число, толщины, смещения, цвета, `lineDashOffset`), затем та же буква заливается градиентом. Свет «пера» остаётся на кончике обводки.
- Добавляется `FontManager`: встроенный набор кириллических гарнитур + опциональная загрузка пользовательских `.ttf/.woff2`; семейство, начертание, размер, трекинг, регистр и строки текста — поля конфига каждой сцены. Все новые шрифты проверяются на лицензию и кладутся в репозиторий/импортируются через `@fontsource` или локальный файл.
- Новые поля: `fontFamily`, `fontWeight`, `fontSizeU`, `letterSpacing`, `outlineLayers[]`, `outlineReveal`, `fillDelay`, `gradient`, `penGlow`, `inPreset`, `outPreset`.

### 3. `ElementRegistry` и редактор

- Каждый визуальный элемент регистрируется с `id`, `type`, `transform {x,y,scale,rotation,z}`, `style`, `animation {in,out,loop}`, `timing`, `hitArea`, `zIndex`, `locked`.
- Режим конструктора включается кнопкой в панели или `?editor=1`: поверх кадра — DOM-оверлей с рамками, ручками трансформации, сеткой и безопасной зоной; сам оверлей **никогда не попадает** в `compositeFrameAt`/WebM.
- Drag-and-drop меняет `transform` и сразу пишет в конфиг; контекстное меню (правый клик) открывает инспектор элемента: пресет анимации, появление/исчезновение, цвета, задержки, масштаб, поворот, слой, блокировка, сброс к defaults.
- Undo/redo, копирование элемента, выравнивание, привязка к сетке, сохранение в JSON.
- Фаза 3a — пресеты и трансформы без keyframes; фаза 3b — покадровые keyframes/кривые для каждого элемента в мини-таймлайне. Конструктор не должен ломать детерминированный `renderAt(t)`: все анимации — чистые функции времени и конфига.

### 4. Модули декора

- `DecorLayer` для №2: выбираемый фоновый элемент (чертёжные дуги/сетка, мягкие солнечные блики и боке, лучи, пыль) с цветом, прозрачностью, скоростью и привязкой к угловым кольцам. По умолчанию — вариант, не спорящий с текущим золотым полем.
- `PhotoPauseDecor`: уголки-скобки по краям экрана (не маленький видоискатель вокруг лого), лого строго в центре и `CircularText` с повтором `фотопауза • …` по окружности; радиус, число повторов, направление, скорость вращения, шрифт и цвет настраиваются.
- `FinaleSequence`: отдельная раскадровка поверх общего рендера — стирание строк → перевод лого в центр → удаление по z/масштабу → обратная прорисовка контура → финальный круг. Все стадии — огибающие от абсолютного `t`, без состояния от количества кадров.

## Порядок работ

Фазы идут последовательно: **0 → 1 → 2 → 3a → 3b → 4**. Сначала настраиваемость и JSON, потому что иначе каждую новую режиссуру придётся переделывать под конструктор; затем типографика, затем сами ролики, затем drag-and-drop. Каждая фаза — отдельный коммит в текущую ветку и дополнение описания PR #2, без слияния.
